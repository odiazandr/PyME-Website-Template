# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Astro 7 with static output, semantic HTML, modern plain CSS, TypeScript 6, Node.js 24 LTS, and npm. Netlify is the planned default host. The base template does not include a client-side framework, CMS, database, or custom backend.

## Users

Agency developers and AI agents are the primary operators. They create, customize, validate, deploy, maintain, and migrate independent client websites. Client business owners receive and own the resulting website asset. Their customers are the ultimate website visitors and need fast access to practical business information and actions, especially on mobile devices.

## Product Purpose

Provide one production-grade website foundation for Mexican PyMEs that turns repeated architecture, quality, deployment, documentation, and maintenance decisions into reusable, enforceable contracts. Success means client sites can become visually distinct and operationally independent without architectural drift or unnecessary runtime complexity.

## Positioning

The product combines deliberately simple static website output with repository-native operational memory, strict validation, explicit extension boundaries, and reviewed template migrations. Its sophistication belongs in engineering controls rather than in browser complexity.

## Operating Context

Operators work in one private GitHub repository per client, use pull requests and deploy previews for material changes, and deploy static artifacts to Netlify under a client-owned domain. Typical visitors use mobile devices to find services, hours, locations, directions, contact details, WhatsApp, booking, menus, or other immediate business information.

## Capabilities and Constraints

- Static rendering, explicit pages, semantic HTML, plain CSS, and minimal client JavaScript are defaults.
- Managed services precede custom infrastructure; application behavior triggers architecture review.
- Business facts have one canonical owner and must be schema validated.
- Agents never fabricate business claims, testimonials, credentials, legal language, prices, or statistics.
- Project 1 never requires the future Project 2 operations dashboard to function.
- Accessibility targets WCAG 2.2 AA-oriented implementation.
- Default locale is `es-MX`; multilingual capability is an explicit extension.
- The visual foundation must support distinctive client identities without making every site look like the template.

## Brand Commitments

The product name is PyME Website Foundation. Its voice is direct, precise, calm, and operationally honest. The reference foundation must feel professional, contemporary, premium, restrained, and intentionally designed without imposing a single client-facing identity.

## Evidence on Hand

The repository contains verified memory enforcement, machine-readable implementation state, a verified static Astro runtime, and verified canonical business-data schemas. It does not yet contain approved client photography, testimonials, performance claims, production deployment evidence, or a finished reference website; future work must not fabricate them.

## Product Principles

1. Put operational sophistication in validation, documentation, and lifecycle controls—not in browser runtime.
2. Make the simplest sufficient architecture the default and require evidence before expanding it.
3. Keep every client repository independent, understandable, and safely maintainable by humans and agents.
4. Separate durable system structure from client-specific visual identity.
5. Describe implementation evidence honestly as planned, implemented, verified, or production-verified.

## Accessibility & Inclusion

The foundation targets WCAG 2.2 AA-oriented implementation, keyboard usability, reduced-motion support, semantic structure, and mobile-first access for users on ordinary devices and connections.
